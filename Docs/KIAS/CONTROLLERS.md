# Программируемые контроллеры KIAS

Этот документ сопровождает текущий проход реализации. До завершения проверок нижеописанный целевой игровой путь нельзя считать проверенным.

## Исходное состояние

База — `KIAS`, `a024edc7a3`. До изменений текущие 26 тестов KIAS прошли. Единый resolver доступа, DATA topology, отдельная management console, coverage, ограничения речи/звука и физические prerequisites сохраняются.

Новый пакет спецификации находится в корне репозитория. Изменённый пользователем README и файлы пакета не заменяют существующие игровые системы. Локальный фикс RobustToolbox сохраняется отдельно.

## Модель

Карточка хранит версию, имя, узлы со стабильными ID, провода, параметры и позиции. Конкретные устройства используют сохраняемые EntityUid, а ANY/ALL — стабильный profile и фильтры комнаты/группы. Временное состояние, очереди, таймеры и найденные устройства на карточку не записываются.

Порты: Signal, Bool, Number, String, Entity, Enum. Преобразования типов не выполняются автоматически. Signal допускает несколько источников, остальные входы — один. Пределы: 128 узлов, 256 проводов, 32 внешних узла, 32 получателя одного выхода, сообщение 256 символов, таймер 0,1–600 секунд. Чистые комбинационные циклы запрещены; обратная связь через state/time nodes допускается с пределом исполнения.

## План игрового пути

Карточка редактируется в отдельном programmer через серверный draft и атомарный WRITE. Исполняется только в запитанном Online rack с восемью физическими слотами. Потребление — base + inserted × per-controller. При остановке сбрасывается volatile state; восстановление запускает ON START.

SPECIFIC не перепривязывается при переносе на другой корабль. ANY объединяет события всех подходящих Online устройств и отправляет команду одному детерминированно выбранному устройству. ALL также объединяет события, а команду отправляет каждому подходящему Online устройству один раз. Отсутствие устройств — допустимое состояние.

Все прежние автоматизации должны стать редактируемыми graph presets. Старый policy executor будет выведен из нормального игрового пути после проверяемой миграции; тяжёлые алгоритмы ПКО и штатные actuator APIs сохраняются.

## Текущая проверка прохода

После добавления редактора клиент и сервер собраны; восемь тестов графа/карточек/исполнения прошли (`controller-editor-build-tests.log`, 45,3 с). Проверены восемь физических слотов, отказ девятой карточке, реальная нагрузка APC, защита грязного черновика, перенос ANY/ALL на второй грид без перепривязки SPECIFIC, отключение DATA, питание и жёсткий OFF.

Добавлены серверная аренда черновика, проверки открытого окна/дистанции/прав/ревизии, атомарный WRITE и нативный canvas с типизированными портами, перетаскиванием узлов и проводов, панорамированием, масштабом, поиском и настройкой узла. Новые проверки защищённого редактора и моста DeviceLink находятся в работе; визуальный игровой smoke пока не выполнен.

Мост DeviceLink наблюдает разрешённый source port даже без физического провода. Семейство определяется стабильным набором source/sink ports, а не именем прототипа машины. Сохранённый снимок такого семейства проверяется по типам, существующим native port prototypes и идентификатору семейства. Команда вызывает штатный sink handler с invoke counter/overload и режимом TEST.

Подключаются физические события датчиков. Каждый подходящий датчик вспышки и Horizon отправляет свой поток; подавление повторов общего оповещения не подавляет события карточек. Типизированные данные приходят перед Signal. На этом этапе старые записи протоколов ещё исполняются: переход к единственному graph executor, шаблоны, импорт, полное сохранение/загрузка и нагрузочные проверки пока не завершены.
