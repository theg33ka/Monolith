Навигация KIAS больше не требует исправленного общего ShipMoveToOperator. Она получает успешное окончание через ComponentShutdown штатного ShipSteererComponent со статусом InRange. Проверяются два корабля, повторный рейс и отмена; тест проверяет событие KIAS. Исходная общая регрессия сохранена отдельно в `independent-autopilot-regression.cs.txt`.

Совместимость defaultLinks адаптера реализована в KIAS: порты без defaults отфильтровываются перед штатным SaveLinks. Сохранены имена On/Off/Status, проверки расстояния и возможности связывания; обычные устройства используют прежний native путь. Регрессия проходит через настоящее действие мультитула «Связать по умолчанию», а не через изменённый общий GetDefaults.

В физическом тесте повторной угрозы ожидание ровно одной секунды заменено расчётом по фактическому TickPeriod с запасом на фазу периодического опроса. Ровно TickRate тиков может давать меньше секунды из-за округления TimeSpan; утверждения о повторном сигнале и cooldown не ослаблены. Начальное ожидание local-threat заканчивается после фактически наблюдаемых выходов, чтобы следующая проверка действительно попадала внутрь десятисекундного cooldown, а не за его пределы.

Дополнительно исправлены fingerprint исходников (XAML, PNG и плоские kias*.ftl), защита production engine от диагностической инструментализации и общий lease для live UI. Проверка lease охватывает 10 входных скриптов.

## Границы доказательств

Параллельный тестовый прогон после возврата общего кода обнаружил штатный статический AudioEffect cache с entity ID другого тестового мира. Окончательные прогоны используют NUnit.NumberOfTestWorkers=0; общий AudioEffectSystem не изменён. Отдельная попытка второго testhost столкнулась с общим gravestone-файлом; тестовые процессы запускаются последовательно. Первый последовательный прогон дал 187/188: выявлена и затем исправлена зависимость defaultLinks, описанная выше.

Новый A–B–B–A, START и физический rotated collision run не запускались. Исправление loader не является доказательством физических результатов нового сценария. Старые наблюдательные замеры с performanceEligible=false не подтверждают выигрыш производительности или причинность Physics.

Подключённый человек-наблюдатель камеры отдельно не воспроизводился; отключение использует штатный native механизм очистки viewers. Окончательная ручная игровая приёмка и измерения производительности остаются отдельными проверками. Исключение настройки без питания по-прежнему ограничено замороженной картой маппинга; initialized/paused maps не получают его.
