## Как использовать

1. Работать **поверх текущей ветки KIAS**, не начинать KIAS заново.
2. Файлы `00_...09_...` и `Docs/KIAS/...` из этого архива считать актуальной спецификацией correction/UI pass.
3. Исторические `history/*` не переписывать: они остаются контекстом предыдущих проходов.
4. `PATCH_PROMPT.md` — готовая копипаста для coding-agent.
5. Папка `references/` содержит пользовательские визуальные референсы: текущее состояние редактора и желаемый уровень читаемости/оформления на примере shuttle console.

## Главный принцип прохода

Это не новый feature-pass. Базовая KIAS и controller graph уже существуют. Задача — исправить реальные gameplay regressions, сделать semantics графа понятными игроку, восстановить совместимость со штатным DeviceList/NetworkConfigurator workflow и довести интерфейсы до игрового качества.

Нельзя объявлять задачу завершённой только потому, что код компилируется. Для UI требуется отдельная проверка layout + живая игровая smoke-проверка.
